# Admin Fraud Review — acceptance checklist

- Apply migration 018 only after verifying `profiles`, `admin_audit_logs`, and `is_active_admin()` exist in the target database.
- Confirm `fraud_reviews` has RLS enabled and no grants to anon/authenticated; only trusted service-role ingestion may insert signals.
- Confirm member/non-admin cannot call either admin RPC.
- Confirm an active admin can list cases, filter statuses, and review a case with a 5–2000 character note.
- Confirm each review creates an `admin_audit_logs` row with before/after values.
- Confirm `restricted` is only a review label: this migration does not suspend accounts, change balances, or issue rewards.
- Confirm service-role signal ingestion validates source events, user identity, risk score and deduplication before inserting; no detector is included here.
- Test duplicate/repeated decisions, concurrent review, missing case, invalid status, and oversized notes in staging.

## Scope boundary
This is a human review queue, not an automated fraud detection engine. No signals are generated by this UI. A separate trusted signal-ingestion service and reviewed detection rules are required before the queue receives live cases.
