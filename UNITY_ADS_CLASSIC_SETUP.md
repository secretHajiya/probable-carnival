# Unity Ads Classic — Vyra Rewards Pro

This project uses **Unity Ads Classic** (Unity Monetization dashboard). LevelPlay /
`unity-levelplay-mediation` has been removed. AdMob and other providers are NOT used.

| Item | Value |
|---|---|
| Unity Game ID | `800410171` |
| Banner placement | `BP_Banner_Android` |
| Interstitial placement | `BP_Interstitial_Android` |
| Rewarded placement | `BP_Rewarded_Android` |
| Android SDK | `com.unity3d.ads:unity-ads:4.12.2` (Maven Central) |

These values live in `UnityAds.js` (top of file). The SDK version lives in
`plugins/withUnityAdsClassic.js` (`UNITY_ADS_VERSION`).

## How it works

```
App.js ──► UnityAds.js ──► NativeModules.VyraUnityAds  (Kotlin: VyraUnityAdsModule)  ──► Unity Ads SDK
                      └──► requireNativeComponent('VyraUnityBanner') (Kotlin: BannerView)
plugins/withUnityAdsClassic.js  (Expo config plugin, runs on `expo prebuild` / EAS Build)
  • adds  implementation("com.unity3d.ads:unity-ads:4.12.2")  to android/app/build.gradle
  • makes sure mavenCentral() is in android/build.gradle
  • copies plugins/unity-ads-native/*.kt into android/app/src/main/java/<package>/unityads/
  • registers VyraUnityAdsPackage in MainApplication
```

Only documented Unity Ads calls are used: `UnityAds.initialize`, `isInitialized`, `load`, `show`
(with `IUnityAdsInitializationListener`, `IUnityAdsLoadListener`, `IUnityAdsShowListener`) and
`BannerView` / `UnityBannerSize` for banners.

## Behaviour

* **Initialization** happens once at app start with Game ID `800410171`. If the app starts offline,
  it retries automatically when the network returns.
* **Banner**: shown at the bottom of the signed-in app, below the tab bar (it does not cover any UI).
  320x50 on phones, 728x90 on wide screens. If it fails to load it disappears and retries a few
  times with back-off.
* **Interstitial**: shown only through `maybeShowInterstitial(reason)`, currently called when the
  user taps OK on the Spin & Win result. At most one full-screen ad every 3 minutes
  (`INTERSTITIAL_COOLDOWN_MS` in `UnityAds.js`). If no ad is ready nothing is shown and the app is not blocked.
* **Rewarded**: 10 points are credited ONLY when Unity reports `COMPLETED`
  (`onUnityAdsShowComplete` with state `COMPLETED`). Skipped, failed, not-ready or closed-early ads
  give nothing. Each native `showId` is credited at most once, and a second credit cannot start
  while one is in progress. The existing Firestore transaction + AsyncStorage logic for
  `bonusPoints` is unchanged.

## Build (cloud, recommended)

Native Android code is required, so **Expo Go will not work** (the app shows no ads there and logs a warning).

```bash
npm install --legacy-peer-deps
npx expo-doctor            # optional
eas build -p android --profile preview --clear-cache      # APK
# or: push to Codemagic (codemagic.yaml already runs expo prebuild + gradlew assembleRelease)
```

Local build (needs Android SDK, JDK 17):

```bash
npm install --legacy-peer-deps
npx expo prebuild --platform android --clean
cd android && ./gradlew assembleRelease
```

`android/` is generated by prebuild and is not stored in this ZIP.

## Testing

1. In `UnityAds.js` set `UNITY_TEST_MODE = true`, build a preview APK, and install it.
2. Check `adb logcat | grep -i -E "UnityAds|VyraUnity"` — you should see
   `[UnityAds] initialized with Game ID 800410171`, then `loaded` events for the rewarded and
   interstitial placements, and `bannerLoaded` for the banner.
3. Press "WATCH AD & EARN 10 PTS", watch to the end: +10 points once. Skip/close early: no points.
4. **Set `UNITY_TEST_MODE = false` again before the production/release build.**

## Still to do in the Unity dashboard

* Make sure the project is linked to the Android app `com.vyrarewards.earn` with Game ID `800410171`.
* Check each placement's **type**: `BP_Banner_Android` = Banner, `BP_Interstitial_Android` =
  Interstitial, `BP_Rewarded_Android` = Rewarded, all enabled for Android.
* Complete the Unity monetization setup (payment info / app store link, app store details) — without it
  Unity may serve no ads in production.
* New placements often need time before they fill; in test mode ads are served regardless.
* Rewarded ads: this app grants rewards on the device (as before). If you later want a
  server-side-verified reward, enable Unity's server-to-server (S2S) callbacks in the dashboard and
  verify on your backend.
* If your app targets children, check Unity's COPPA / consent settings.

## Known limits / honesty notes

* This ZIP was prepared in a sandbox with **no network**: `npm install`, Gradle and the Kotlin compiler
  could not run, so the Android build and live ad fill have **not been tested**. The config plugin
  transforms were checked against sample Expo templates; Kotlin and JS were checked for balance
  only, not compiled.
* The Unity Ads version `4.12.2` was chosen from knowledge, not resolved against Maven Central here. If
  Gradle cannot find it, set `UNITY_ADS_VERSION` in `plugins/withUnityAdsClassic.js` to the newest 4.x
  release listed on https://central.sonatype.com/artifact/com.unity3d.ads/unity-ads
* `VyraUnityBannerManager.kt` implements `BannerView.IListener` through a dynamic proxy so it compiles
  regardless of which optional callbacks a 4.x release declares.
